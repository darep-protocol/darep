# DAREP

**Durable Agreement, Receipt & Evidence Protocol.** Spec home: https://darep.org

DAREP is an open protocol for AI agents that belong to different people and organizations to hand each other signed work. A record is signed by its sender's key and delivered durably to the recipient's provider. The recipient answers with a signed receipt once the record is stored. Both sides keep the records, receipts, rejections and delivery attempts as evidence they can show to a third party later. Terms, evidence bundles and settlement build on this core in later versions.

## Status

| | |
|---|---|
| Specification | **Wire v2, frozen (spec v0.1).** Signed records, the delivery contract and the HTTPS binding. See [CHANGELOG.md](CHANGELOG.md). |
| Test vectors | Records and delivery vectors, regenerated byte for byte by their generators. |
| Implementations | Two in this repository, tested against the same vectors: a Node.js reference provider and a Python peer. A live test runs handoffs between them in both directions. |
| Experimental extensions | `work/v2` handoff and `reschedule/v2` types are outside frozen Wire v2 conformance. Normative publication of `work/v2` is future work. |
| Conformance kit | Planned. Conformance means meeting all applicable normative requirements. The vectors and runners are verification aids, not a complete conformance determination. |

## Run the vectors and tests

You need Node.js 22.18 or later, and Python 3.11 or later with [uv](https://docs.astral.sh/uv/) for the Python peer. Run every command from the repository root.

Vectors:

```bash
npm ci
npm run vectors:check       # records vectors against spec/records.md §8; delivery vectors' signatures and verdicts
npm run vectors:generate    # regenerate everything; `git diff --exit-code vectors/` must then be empty
```

Node reference provider:

```bash
(cd reference/node && npm ci && npm test)
```

Python peer and live interop (install the Node provider's dependencies first, as above):

```bash
uv sync --locked --project reference/python --extra agent
reference/python/.venv/bin/python reference/python/test_peer.py       # unit tests and every applicable vector
reference/python/.venv/bin/python reference/python/run_vectors.py     # one line per vector
node reference/python/check-vector.mjs                                # the reference verifier accepts Python-signed bytes
reference/python/.venv/bin/python reference/python/verify_interop.py  # live Node↔Python handoffs
```

The private keys in `vectors/` are **test-only** keys, published on purpose so anyone can regenerate the vectors. They protect nothing. See [vectors/README.md](vectors/README.md).

## Milestone labels in the spec

The spec text uses milestone labels. **A1** is Wire v2 as frozen here: a receiver resolves every `kid` against identity documents its owner has pinned, never over the network. **A2** adds network resolution of identity documents. **A3** is publication and independent implementation. Statements such as "in A1" describe Wire v2 behavior.
